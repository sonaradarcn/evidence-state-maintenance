# Reviewer round 1: supplementary held-out runs (Experiments A and B)

Date: 2026-10-05. These runs answer major issues 4 and 3 of `reviews/paper_r1_summary.md`. Plan, LLM budget and
decision log: `PLAN.md`, written before any LLM call. Every number below is generated by `analyze.py`. Its full output
is in `RESULTS_tables.md` and `results.json`, and its per-read records are in `records_r1.parquet`.

Setup:

* **Model and servers.** qwen3.6:27b at T = 0 on my own Ollama servers, 11595 (GPU0) and 11596 (GPU1). Both were
  stopped at the end. Port 11434 was never touched.
* **Policy.** Frozen ESM = `ESM-norepair`, the same configuration, judge, deriver, LLM cache and derivation store as in
  the held-out stage.
* **Bootstrap.** B = 2000 throughout. Fact bootstrap CIs are in [ ], repository-cluster bootstrap CIs (16 repositories)
  in { }.

## 0. Verdict

* **Experiment A: anchor expiry does not help, as item 6 predicted.**
  * **Expiring every anchor.** At N = 200 / 100 / 50, served-wrong changes by −0.02 / +0.31 / +0.42 pp against the
    frozen ESM. None of these changes is significant, and the CIs span about ±1.5 pp.
  * **Cost.** Expiry costs +10.6k / +32.0k / +73.1k tokens per fact, or 1.4×, 2.2× and 3.8× the frozen ESM.
  * **Why.** When the stored answer is wrong, the forced re-derivation repeats the error: 78–87 % of these re-derivations
    stay wrong, and mostly with the identical answer string. At the same time, forced re-derivations break answers that
    were right. As a result, only 1.3–5.8 % of the frozen ESM's anchored-wrong reads are removed.
  * **Against the estimate.** The run is milder than the item-6 estimate (+0.3 to +1.8 pp), but it has the same sign
    and leads to the same conclusion.
  * **The cheap "NONE-suspicious" variant.** It is never worse on any fact, and it reduces served-wrong by
    −0.08 / −0.24 / −0.37 pp, for +1.3k / +5.3k / +13.3k tokens per fact. The upper CI bound is 0.00 pp in every case,
    so this is a small, borderline effect, not a fix.
* **Experiment B: on a natural random sample of 100 facts, the comparison with the strong baselines holds.**
  * **Accuracy.** ESM's served-wrong rate does not differ detectably from CERT-ZS, CERT-v0h, LLMDIFF or REPLAY. The
    paired differences are −0.03, 0.00, −0.91 and −0.13 pp. ESM is non-inferior to all four at the 1.5 pp margin, under
    both bootstrap units.
  * **TTL100.** ESM is significantly more accurate than TTL100: −2.2 pp, cluster CI [−3.7, −0.9].
  * **Cost.** The baseline/ESM token ratios on NAT100 are similar to those on the change-enriched H150, or higher:

    | baseline | NAT100 | H150 |
    |---|---|---|
    | CERT-ZS | 2.26 | 2.00 |
    | LLMDIFF | 3.72 | 2.72 |
    | REPLAY | 6.01 | 6.12 |
    | TTL100 | 1.91 | 1.66 |
    | CERT-v0h | 1.15 | 1.09 |

  * **What this means for the claim.** The "2–3× fewer LLM tokens than CERT-ZS / LLMDIFF" claim therefore carries over
    to natural facts: 2.3× and 3.7×. Against CERT-v0h there is still no meaningful cost advantage.
  * **Caveat.** The sample's absolute costs are lower than the population's (§B3), and its accuracy comparisons rest on
    only 24 changing facts.

## A. ESM + anchor expiry (major issue 4)

### A.1 What was run

* **Facts and policy.** H150 (160 facts), reads at every commit (400 per fact), real 27B re-derivations. The base
  policy is the frozen ESM.
* **Expiry rule (`ESM-norepair-exp{N}`, `esm/maintain.py`).**
  * At the first read at which the current anchor is at least N commits old, the agent re-derives before the evidence
    check. s0 counts as the anchor at t = 0.
  * Every re-derivation, forced or triggered by ESM, becomes a new anchor and resets the age.
  * A forced re-derivation uses the same `DerivStore`, prompt and agent as every other re-derivation.
* **Forced outcome.**
  * A non-empty answer is adopted, and the evidence is re-anchored on the new trace. This includes `NONE`, the
    benchmark's legitimate answer for "the referent is gone", which is exactly the answer the item-6 failure needs.
  * **Fallback, defined before the run.** If the forced re-derivation returns no answer (None or empty) or fails, the
    previous answer *and* its evidence anchor are kept. The answer is marked *unverified*, and the age restarts at t.
* **Optional variant (`ESM-norepair-expS{N}`).** Expiry applies only to NONE-suspicious anchors, defined by a
  zero-oracle rule:
  * an ESM-triggered re-derivation that returned no answer; or
  * one that returned a value other than `NONE` after a judge verdict whose reason says the referent disappeared
    (regex: removed / moved / renamed / no longer / not found / missing / does not exist …).

  A forced answer that is again a non-`NONE` value stays suspicious; `NONE` clears the flag.
* **Code check.** The code change leaves every existing policy unchanged. The modified `simulate_esm` reproduced the
  stored frozen records exactly: 25 facts, all fields, offline.

* **The direction matches.** Item 6 estimated that expiring every anchor makes ESM no better and somewhat worse, at

* **The harm was overestimated.** The run's harm is about half the estimate or less (+0.0 to +0.4 pp, against

  suspicious anchors avoids breaking right answers: 0 broken reads.

### A.5 How well the NONE-suspicious rule picks out wrong answers

The frozen arm made 209 re-derivations on H150, and 48 of them were wrong (41 with oracle NONE).

* **Recall.** The rule flags 25 of the 48 wrong ones (52 %), including 21 of the 41 NONE cases.
* **False flags.** It also flags 36 right ones, so its precision is 41 %.

A better detector would not be enough on its own. Even a perfectly flagged wrong anchor is re-derived *wrong* again
about 90 % of the time. The fix has to change the re-derivation itself, for example a NONE-aware prompt that checks
the pinned path, or a different model, as item 6 concluded.

**Answer to the reviewer.** A real run of ESM with anchor expiry at N ∈ {50, 100, 200} fills the missing point on
the risk–reuse–cost frontier. Expiry is dominated: it adds 11k–73k tokens per fact and gives no accuracy gain (Δ −0.02
to +0.42 pp, n.s.). The restricted variant buys at most −0.4 pp at +50 % cost. The anchored error is an answer-source
error that a periodic refresh repeats.

## B. Strong baselines on a natural random sample (major issue 3)

### B.1 Sample

* **NAT100.** 100 facts were drawn uniformly without replacement from the 715 kept facts of the held-out natural
  subset, with `random.Random(20261005).sample` over the sorted ids.
* **Drawn first.** The draw was made at 12:28, before any LLM call and before any outcome was looked at. The script is
  `draw_nat100.py`. The seed and the population hash are in `draw_nat100.json`, and the ids in
  `esm_data_heldout/sub_NAT100.json`.
* **Composition.** 92 static and 8 behaviour facts, from all 16 repositories (3–10 facts each). 11 facts overlap H150.
  24 facts change in FUTURE (population: 28 %).
* **Arms.** All arms read at every commit and use real 27B re-derivations.
  * **CERT-ZS and CERT-v0h.** Certificates were built for NAT100 with the held-out stage's code. CERT-v0h covers the 92

    likewise.
  * **REPLAY** fit the budget and ran at every commit on all 100 facts. No every50 fallback was needed.
  * **ESM and NEVER** were re-simulated offline. Every call was a cache hit from the ALL run.

## D. Decisions, deviations, skipped items

**Skipped or not needed:**

* **REPLAY fallback on the every50 grid.** Not run: REPLAY at every commit fit the budget.
* **No other arm was cut.** No `--deadline` was reached; every arm is complete. The only exception is CERT-v0h's 8
  behaviour facts, which are not applicable by design.

**Design choices fixed in PLAN.md before the run:**

* **A forced `NONE` is adopted, not kept back.** Only an empty answer or a failure triggers the keep-previous fallback.
  `NONE` is the legitimate benchmark answer for a vanished referent and the target of the fix. A "keep previous on
  `NONE`" variant was not run.
* **The NONE-suspicious rule** uses only the judge's reason text and the answer string, with no oracle. It covers only
  re-derived anchors, never s0.

**Statistics:**

* **Margins and clusters.** The NI/TOST margin of 1.5 pp is post hoc, the same as in item 2. There are 16 clusters, so
  the percentile cluster bootstrap may under-cover. Sign tests are reported; only the TTL100 comparison is significant
  at the repository level (p = 0.008).
* **NAT100 has low power for accuracy differences** (24 changing facts). Non-inferiority here rests on ESM never being
  worse on any fact, not on tight intervals around a non-zero effect.

**Representativeness:** NAT100's absolute costs are below the natural population's (§B.4). Ratios, not absolute
costs, should be cited from this sample.

**Shared resources:**

* **Same model.** Experiments A and B reuse the same 27B judge and deriver. This answers nothing about model
  independence (minor issue).
* **Same derivation store.** As in the held-out stage, two policies that re-derive the same fact at the same commit
  share one derivation.

**Incident (no results affected):** On its first runs, `analyze.py` wrote its outputs into `revision_r1/`, because
`from r1_common import *` overrode its `HERE`. The misplaced files were deleted; no existing file had the same name.
The script now writes here. `revision_r1/cache/` may contain extra `pf__*.pkl` caches of existing held-out records,
created by `r1_common.pf`.

**Infrastructure:**

* Ollama 11595 / 11596 were started at 12:31 and stopped at about 16:40 (`stop_ollama.ps1`), and both job queues were
  stopped.
* Port 11434 was never touched.
* The frozen held-out `sim/` parquets were not modified. New outputs are in `esm_data_heldout/sim_r1/`.

* `results.json`: every statistic, including the per-repository paired effects.
* `records_r1.parquet`: per-read records of every new arm.
  * Columns are those of `maintain.Rec`, plus `experiment`.
  * `action` ∈ {`forced`, `forced_keep`} marks the forced re-derivations, and `verified = 0` marks reads served while
    unverified.
  * The frozen H150 ESM records are in `../records.parquet`; the NAT100 ESM / NEVER records are in
    `esm_data_heldout/sim_r1/`.
* `fig_A_expiry.png`, `fig_B_natural.png`: cost against served-wrong.
* Code: `esm/maintain.py` (`ESMConfig.expiry` / `expiry_mode`, `_none_suspicious`) and `esm/policies.py`
  (`ESM-norepair-exp{50,100,200}`, `ESM-norepair-expS{50,100,200}`).
* Raw data:
  * `esm_data_heldout/sim_r1/*.parquet`, with order files;
  * `queue_R1A.*` and `queue_R1B.*` (commands and logs);
  * `sub_NAT100.json`;
  * new derivation and certificate shards (`derivations.<pid>.jsonl`, `certs.<pid>.jsonl`);
  * the LLM cache and ledger.
